# WebSocket 心跳机制使用指南

## 概述
为了保持长连接稳定，防止因网络空闲而导致的连接断开，我们在 `WebSocketService` 中集成了心跳机制。

## 心跳机制特性

### 🔧 **配置参数**
- **心跳间隔**: 25秒 (配合服务器30秒空闲检测)
- **心跳超时**: 10秒 (等待 pong 响应的最大时间)
- **心跳格式**: 发送 "ping" 字符串，期待 "pong" 字符串响应
- **服务器配置**: `IdleStateHandler(30, 0, 0, TimeUnit.SECONDS)` - 30秒读空闲检测

### 💓 **工作流程**

1. **连接建立后自动启动**
   - WebSocket连接成功后，自动启动心跳定时器
   - 每25秒发送一次心跳 ping 消息（确保在服务器30秒空闲检测前发送）

2. **心跳发送**
   ```dart
   // 发送心跳
   _channel?.sink.add("ping");
   ```

3. **心跳响应处理**
   - 服务端收到 "ping" 后应回复 "pong"
   - 客户端收到 "pong" 后确认连接正常
   - 显示延迟时间（用于网络质量监控）

4. **超时处理**
   - 如果10秒内未收到 pong 响应，认为连接异常
   - 自动触发重连机制
   - 防止死连接占用资源

### 📊 **日志输出示例**

连接成功：
```

```

发送心跳：
```

```

收到响应：
```

```

```

```

### 🔄 **生命周期管理**

| 事件 | 心跳行为 |
|------|----------|
| WebSocket 连接成功 | 自动启动心跳 |
| WebSocket 断开连接 | 自动停止心跳 |
| WebSocket 发生错误 | 停止心跳并准备重连 |
| 服务关闭 (onClose) | 清理所有心跳定时器 |

### 🛡️ **容错机制**

1. **重复心跳检测**
   - 如果上一个心跳还未收到响应，跳过本次心跳
   - 避免心跳消息堆积

2. **网络异常处理**
   - 心跳发送失败时，立即触发重连
   - 确保网络问题能被快速发现

3. **定时器清理**
   - 连接断开时自动清理所有相关定时器
   - 防止内存泄漏

## 服务端要求

### IdleStateHandler 配置
服务端使用 Netty 的 IdleStateHandler 进行空闲检测：

```java
// 30秒读空闲检测，0秒写空闲，0秒读写空闲
pipeline.addLast("heart-notice", new IdleStateHandler(30, 0, 0, TimeUnit.SECONDS));
```

### 心跳响应实现
服务端需要实现心跳响应逻辑：

**Java (Netty) 示例:**
```java
if (frame instanceof TextWebSocketFrame) {
    String text = ((TextWebSocketFrame) frame).text();
    if ("ping".equals(text)) {
        // 收到心跳，回复pong
        ctx.writeAndFlush(new TextWebSocketFrame("pong"));
        return;
    }
}
```

**Node.js (ws) 示例:**
```javascript
ws.on('message', (message) => {
    if (message.toString() === 'ping') {
        // 收到心跳，回复pong
        ws.send('pong');
        return;
    }
    // 处理其他消息...
});
```

## 配置自定义

如需调整心跳参数，可在 `WebSocketService` 中修改：

```dart
// 心跳间隔（默认25秒，配合服务器30秒空闲检测）
static const Duration _heartbeatInterval = Duration(seconds: 25);

// 心跳超时（默认10秒）
static const Duration _heartbeatTimeout = Duration(seconds: 10);
```

### 时间配置建议
- **客户端心跳间隔** < **服务器空闲检测时间**
- 建议客户端间隔比服务器检测时间短5秒以上
- 例如：服务器30秒检测 → 客户端25秒发送

## 监控和调试

### 查看心跳状态
可以通过日志监控心跳状态：
- 💓 发送心跳 - 绿色表示正常发送
- 💚 收到响应 - 显示网络延迟
- ⚠️ 上一个心跳还未响应 - 黄色警告
- 💔 心跳超时 - 红色错误，将触发重连

### 网络质量评估
通过心跳延迟可以评估网络质量：
- < 50ms: 优秀
- 50-200ms: 良好  
- 200-500ms: 一般
- > 500ms: 较差

## 最佳实践

1. **服务端必须实现心跳响应**，否则客户端会频繁重连
2. **心跳间隔不宜过短**，避免增加服务器负担
3. **心跳超时时间要合理**，太短会误判，太长影响故障发现
4. **在移动网络环境下**，可以适当延长心跳间隔以节省流量

## 故障排除

### 常见问题

**问题1: 频繁重连**
- 检查服务端是否正确响应 "pong"
- 确认网络延迟是否超过超时时间

**问题2: 心跳不生效**
- 确认 WebSocket 连接状态正常
- 检查是否有其他地方停止了心跳定时器

**问题3: 内存占用增长**
- 确认断开连接时正确清理了定时器
- 检查是否有定时器泄漏
